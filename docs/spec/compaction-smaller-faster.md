# 压缩保留预算与摘要开销调整

## 现状与目标

默认保留窗口 16% 的近期原文，在 272k 窗口中至少保留 43,520 token。近期本地日志抽样 36 次成功压缩耗时 89–142 秒，中位数约 118 秒，均为首块首尝试；摘要约数千 token，保留原文及固定请求头才是剩余占用主体。摘要调用没有显式 reasoningEffort，不能沿用主会话 low 的预期。

目标：默认近期保留预算降至 12,000 token 上限、为模型声明支持的 low 推理显式传参、引导摘要集中于续接所需信息。实测速度和语义质量须与本地回归分别报告。

## 实施边界

- 未配置保留形式时使用 min(12,000, floor(contextWindow × 0.16))；小窗口保留原缩放行为。显式 retainRatio、retainTokens 及精确模型覆盖保持原语义。
- 默认保留形式延迟到目标容量解析时决定；沿用默认比例与 thresholdRatio 的加载校验，绝不静默修正显式无效参数。
- 摘要路由公开 low 时使用该 ID；缺失该能力时不猜测其他不透明 ID，沿用 provider 默认。估算与派发采用同一元数据，容量 fingerprint 纳入所选推理强度。
- 提示词软目标约 1,500 token，优先保留未完成目标、约束、当前状态和精确引用；必要事实可超过软目标。保持八段结构及 8,192 输出上限，拒绝截断仍有效。
- 不改事务锁、工具配对、持久化、失败重试和 provider 接口；不改生产 profile。

## 验证

- 默认大/小窗口预算、显式覆盖、跨模型继承与无效参数。
- 实际自动压缩后近期尾部预算、平衡边界、重载与追加；对照旧 16% 策略。
- 摘要路由支持 low、缺少推理元数据、不支持 low、能力变化后的 fingerprint，估算与派发一致。
- 全量类型检查、测试、覆盖率、构建及包内容检查。
- 不用桩模型的耗时证明远端加速；未执行真实模型 A/B 时明确保留此边界。
